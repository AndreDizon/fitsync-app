# FitSync notifications

## Enable social activity notifications

After the existing Social and Progress migrations, run the entire
[`20261118_notifications.sql`](backend/migrations/20261118_notifications.sql)
in the Supabase SQL Editor. It is safe to rerun this migration. It creates a
private recipient-scoped notification table and insert triggers for hearts and
comments. It does not delete existing posts or change their cleanup schedule.

Only new activity after installation generates social notifications. Self-likes
and self-comments do not notify the author. Repeated unlike/like toggles by the
same person on the same post do not create repeated notifications. Following a
social notification clears the alerts for that post. Viewing an owned post in
the feed clears its like alerts; opening its comments clears comment alerts.
Later activity can notify again, while older activity already viewed stays
suppressed on this device. Deleted or
expired posts cannot be opened through notification links.

The signed-in API returns at most 200 social events from the last 30 days, with
row-level security restricting access to the recipient. Notification previews
do not contain comment text. Test with two separate signed-in accounts: one
posts, the other likes or comments, then the author checks the bell.

## In-app reminders

- Workout start: up to 15 minutes before the first scheduled exercise.
- Exercises, food entries and water: a 15-minute window beginning at their saved
  time. Completed entries are skipped; old reminders are not backfilled.
- Achievements: saved, unlocked milestones that have not been claimed.
- Streak: 8:00–8:14 PM in the selected timezone, if yesterday was visited and
  today has not been visited. Hidden tabs no longer count as app visits.

Checks run once a minute while the app is open and when it regains focus or
connectivity. Reminder IDs prevent repeated alerts for the same scheduled entry,
time and date. Clearing an alert keeps its deduplication ID. Changing a scheduled
time creates a new reminder. Opening an older reminder selects its saved date.

Settings has separate controls for all eight categories. Preferences, read state,
and up to 200 inbox entries are stored per account on this device; they do not
sync across devices. Sign-out clears private notification copies. Social events
remain available on the account feed until their linked post is deleted or the
30-day query window passes.

## Device alerts

In **Settings → Notifications**, choose **Enable device alerts**. Only this action
requests browser permission. Denial leaves the in-app inbox working. The user can
turn device delivery off without disabling the inbox or individual categories.

HTTPS (or localhost) and browser support are required. A separate notification
service worker handles mobile-compatible alerts and click navigation without
replacing the exercise offline worker. iOS support depends on browser/home-screen
installation requirements. Browsers may throttle or suspend background tabs.

**Closed-app push is not configured.** These are device alerts generated by an
open app, not a guarantee of delivery while the app is closed. Reliable closed-app
delivery needs Web Push subscriptions, VAPID credentials, server-side preference
and schedule storage, and a scheduled delivery service. No credentials or external
push subscriptions are created by this change.
