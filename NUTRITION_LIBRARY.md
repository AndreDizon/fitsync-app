The nutrition library contains 100 generic foods across nine primary categories. Run `npm run seed:foods` to regenerate `backend/data/foods.json`, or `node scripts/validate-foods.mjs` to check source values and portion calculations. Frontend development and builds also regenerate the seed. Numbered pages display up to 24 foods each; searches and filters query all 100 records and reset to page one.

`scripts/food-classifications.mjs` defines the original ten foods' overlapping tags. `scripts/food-expansion.mjs` curates the additional 90 identities, preparation states and notes, and `scripts/expanded-food-metadata.mjs` maps these to source portions and classifications. Every group now has entries. Tags appear in filters and food details alongside eating-preference and allergen metadata. Filters combine across classifications; ingredient-allergen exclusions do not guarantee product safety. Protein foods is a browsing group, not a quantified high-protein claim; legumes, soy and dairy may overlap it.

To rebuild the checked-in source subset from the original USDA archive, extract its CSV files and run `node scripts/import-food-source.mjs <extracted-directory>`, then `npm run seed:foods`. This importer preserves original source descriptions, numeric nutrient values and household gram weights. Normal builds do not access the network. Where the source supplies no household measure (cooked tempeh), the interface uses grams and the 100 g reference rather than inventing a cup or serving size. New foods use labeled food-group SVG illustrations; the original ten retain their individual illustrations.

Nutrition and household measure weights come from USDA FoodData Central SR Legacy (April 2018), published April 2019. `backend/data/foods-source.json` preserves the selected source rows, archive URL and archive SHA-256. `scripts/curated-foods.mjs` contains FitSync descriptions, preparation notes, qualitative budget labels, benefits and supporting links. Preparation times are planning estimates. Illustrations are code-native SVG artwork.

Every nutrient value uses a 100 g edible-weight basis, scaled to the chosen gram-backed serving. Raw/dry, cooked and ready-to-eat states remain distinct. Missing nutrients remain null. Generic records do not establish product-specific allergy or halal suitability.

Nutrition mode has a reference-only food library. Its default content never changes based on onboarding. Manual search and classification filters browse all 100 records; aliases include kanin, munggo, tokwa and saging. Food details include default source portions and an informational gram calculator. Users build their own account-backed menus inside Playlist, where portions and meal times are stored.

Seeding also writes `/offline/foods.json` and a content-hashed `/offline/food-manifest.json`. The existing service worker saves this public catalog in its own versioned food cache when Nutrition opens. Its ready note appears only after saving; failed downloads offer retry, and an offline visit can confirm the saved copy. Food saving does not trigger the exercise media download. SVG food artwork is bundled and has no external image requests. The service worker never caches authenticated HTML, account data, API sessions or navigation pages. Opening the full app from a closed browser while offline is not supported by either library cache.

Manual account menus and offline synchronization are documented in PLAYLISTS_SETUP.md. Automatic meal generation remains separate; the library does not generate personal calorie targets or prescriptions.
